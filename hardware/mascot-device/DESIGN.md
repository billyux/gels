# 모아리 스마트 인형 하드웨어 설계 (프로토타입 구상)

⚠️ **이 문서는 실제 조립 전에 구조를 먼저 정리해보는 설계 문서입니다.**
인형 내부에 전자부품을 넣어본 적은 없고, 어떤 부품을 어디에 배치하면
좋을지·서로 어떻게 연결되는지를 글로 먼저 정리한 것입니다. 실제로
분해/조립해보면서 치수나 배치는 조정이 필요할 수 있습니다.

## 1. 무엇을 만드는가

지금 갖고 계신 모아리 인형(하얀 곰돌이 모양, 귀에 분홍 꽃, 초록색 하의)
안에 아래 네 가지를 넣어서, 인형 자체가 "말을 걸면 듣고, 주변 온도를
재고, 영상을 보내는" 작은 케어 기기가 되도록 만드는 것입니다.

- **ESP32-S3** (카메라 스트리밍용, 기존 `esp32-camera-stream` 펌웨어 재사용)
- **온도 센서** (인형 주변/실내 온도 측정)
- **블루투스 마이크** (음성으로 말을 걸면 AI 상담으로 이어지도록)
- **라즈베리파이**와의 무선 연동 (같은 와이파이망으로 데이터 전송)

전체 흐름은 기존에 만들어둔 `hardware/README.md`의 구조와 이어집니다:

```
[모아리 인형 안]                         [인형 밖]
  ESP32-S3(카메라) ----MJPEG 스트림---->  라즈베리파이 --MediaPipe Pose-->
  온도 센서 -----------(같은 ESP32에 연결)      |
  블루투스 마이크 -------------------------> 라즈베리파이(음성 녹음/STT)
                                              |
                                        Supabase (activity_samples,
                                        온도 로그, AI 상담 트리거)
                                              |
                                          웹 대시보드
```

## 2. 왜 라즈베리파이는 인형 밖에 두는가

라즈베리파이를 인형 안에 직접 넣는 방법도 있지만, 프로토타입 단계에서는
**추천하지 않습니다**:

- 라즈베리파이 + 방열판/쿨링팬 구성은 부피가 커서 봉제 인형 속에 넣으면
  솜을 많이 들어내야 하고, 인형이 딱딱해집니다.
- 라즈베리파이는 장시간 켜두면 발열이 있는데, 인형 원단(봉제 솜)은
  열이 잘 안 빠져서 과열 위험이 있습니다.
- 이미 "라즈베리파이는 핫스팟으로 연동, SD카드도 준비됨" 상태라고
  하셨으니, 라즈베리파이는 **협탁이나 콘센트 근처에 고정**해두고,
  인형 안에는 **가볍고 저전력인 ESP32-S3 쪽만** 넣는 구조가 훨씬
  안전하고 실전에 가깝습니다.

즉, **인형 = ESP32-S3 + 센서 + 마이크 (몸체)**, **라즈베리파이 = 인형
밖의 두뇌 역할(수신·분석·전송)** 로 역할을 나눕니다.

## 3. 인형 내부 부품 배치안

인형을 이미지 기준으로 보면 크게 **머리(귀+꽃 장식)**, **몸통(볼/배)**,
**하의(초록색 다리 부분)** 로 나뉩니다. 배치 제안은 다음과 같습니다.

| 부품 | 넣을 위치 | 이유 |
|---|---|---|
| ESP32-S3 (카메라 포함) | 몸통 앞면, 배 부분 안쪽 (얼굴 정면을 바라보도록) | 카메라 렌즈가 인형 배쪽 원단을 살짝 뚫고 나오게 해서 인형이 "정면을 보는" 느낌을 유지. 얼굴에 렌즈를 노출하면 표정을 가려서 몸통 쪽이 자연스러움 |
| 온도 센서 (DS18B20 또는 DHT22) | 등 쪽, 통풍이 되는 위치 (봉제 솜에 완전히 파묻히지 않게) | 인형 체온이 아니라 **주변 실내 온도**를 재야 하므로, 솜에 깊이 묻히면 오차가 커짐. 등 쪽 얇은 원단 안쪽에 고정 |
| 블루투스 마이크 모듈 | 머리 쪽, 귀 근처 (꽃 장식 반대편 귀) | 사람이 인형에게 말을 걸 때 보통 얼굴 가까이 대고 말하므로, 마이크는 머리에 있어야 음성 인식률이 좋음 |
| 배터리팩 (USB-C 충전식) | 하의(초록색 다리) 안쪽, 지퍼 파우치 | 다리 부분이 가장 부피가 크고 잘 안 보이는 위치. 등 쪽에 작은 지퍼를 달아서 충전 케이블을 그때그때 연결 |
| 배선 | 몸통→머리, 몸통→다리 구간은 얇은 실리콘 피복 전선으로 | 인형을 안았을 때 딱딱한 느낌이 안 나도록 전선을 넉넉하게 여유 있게 배선 |

## 4. 부품별 상세 메모

### ESP32-S3 (카메라)
기존 `hardware/esp32-camera-stream/esp32-camera-stream.ino`를 그대로
씁니다. 이 보드에는 여분의 GPIO가 있으니, 온도 센서도 **같은 보드에
같이 연결**해서 데이터를 한 번에 라즈베리파이로 보내는 방법을 추천합니다.
(별도 보드를 하나 더 넣으면 배선/전원이 두 배로 복잡해집니다.)

- 온도 센서(DS18B20, 방수 캡슐형 추천 — 원단 안에 넣기 좋음)를 ESP32
  여유 GPIO 핀(예: GPIO1)에 연결
- 5초~1분 주기로 온도값을 읽어서, 기존 MJPEG 스트림 서버에
  `/temperature` 같은 간단한 HTTP 엔드포인트를 하나 추가해 라즈베리파이가
  같이 읽어가게 하면, 새 통신 경로를 안 만들어도 됩니다.

### 블루투스 마이크
ESP32-S3 자체에는 블루투스 오디오 입력 기능이 기본으로 잡혀있지 않기
때문에, 두 가지 방법 중 하나를 고르면 됩니다.

1. **(추천) 시중 블루투스 마이크 모듈을 라즈베리파이에 직접 페어링**
   — 마이크 모듈 자체는 인형 머리 속에 넣되, 블루투스는 ESP32가 아니라
   라즈베리파이와 직접 연결. 라즈베리파이는 이미 오디오/블루투스 지원이
   잘 되어 있어서 별도 드라이버 작업이 거의 없음.
2. ESP32에 아날로그 마이크(예: INMP441 I2S 마이크)를 유선으로 연결하고,
   ESP32가 오디오를 라즈베리파이로 스트리밍 — 배선은 하나 늘지만 인형
   안 부품을 한 보드로 통일할 수 있음.

프로토타입 단계에서는 **1번(라즈베리파이 직결 블루투스 마이크)**이
설정이 더 간단해서 먼저 시도해보시는 걸 권장드립니다.

### 온도 센서
위에서 설명한 대로 ESP32 GPIO에 직결. 이미 웹 대시보드에 있는
"🌡️ 온도 알림" 기능은 현재 Open-Meteo(외부 기상 API)로 지역 날씨를
가져오는 방식인데, 인형에 센서가 붙으면 **실내 실측 온도**를 추가로
보여줄 수 있어서, 나중에 "실외는 32도, 실내(인형 센서 기준)는 27도"처럼
비교해서 보여주는 것도 가능합니다. (지금 당장 할 일은 아니고, 이후
단계 아이디어로 메모만 남겨둡니다.)

### 전원
- USB-C 보조배터리(3.7V 리튬 or 5V 출력 소형 파워뱅크) 하나로 ESP32와
  마이크 모듈(2번 방법을 쓸 경우)을 같이 급전
- 배터리는 반드시 **과충전/과방전 보호회로가 내장된 제품**으로 사용
- 인형 밖으로 충전 케이블이 나올 수 있도록, 다리 안쪽 파우치에 작은
  지퍼나 벨크로를 달아 케이블 입출력 구멍을 만들어두는 걸 권장

## 5. 안전/내구성 주의사항

- 세탁 불가 — 전자부품이 들어간 이후로는 인형 전체 세탁은 하지 말고,
  겉면만 부분 세척
- 전선은 실리콘 피복(열에 강하고 유연함)으로, 날카로운 부품 모서리는
  전부 절연 테이프나 열수축 튜브로 마감
- 어르신이 인형을 안거나 눌렀을 때 배터리/기판에 직접 압력이 가지
  않도록, 부품 주변에 완충재(스펀지 등)를 살짝 덧대기
- 방수 기능은 없으므로, 음료 근처/욕실 등에서는 사용 자제 안내 필요

## 6. 소프트웨어 연동 (기존 코드와의 연결점)

- 카메라 스트림: 기존과 동일하게 `raspberrypi-activity-logger`가
  `ESP32_STREAM_URL`로 접속해서 자세 분석
- 온도 데이터: ESP32의 `/temperature` 엔드포인트를 라즈베리파이가 주기적으로
  같이 읽어서, 기존 `activity_samples` 테이블 옆에 컬럼을 추가하거나
  새 테이블(`indoor_temperature_log`)로 Supabase에 적재하는 방식을 추천
- 마이크(음성): 라즈베리파이가 음성을 받아 STT(예: 파이썬
  `speech_recognition` 라이브러리)로 텍스트 변환 후, 기존 웹의 AI 상담
  Edge Function(`ai-chat`)에 그대로 넘기면 "인형에게 말 걸면 AI가
  답하는" 흐름을 그대로 재사용할 수 있음
